# Owner correction for a time-boxed 1C product slice

Use after an initial open PR passes native behavior but owner review authorizes one bounded product/reporting correction.

## Correction contract

1. Freeze the reviewed head/tree/base and reproduce the gap against those bytes. Preserve explicit prohibitions (for example no reviewer cycle, no RED/repeat, and exactly one replacement native run).
2. Prefer the domain's existing user-message boundary. Keep an early posting rule in the object `Posting`, emit localized `NStr` text through the already-used message helper and cancel boundary, and return before initialization/movements. Do not move the rule into a form/common module or build message-capture infrastructure merely to prove pixels.
3. When pixel rendering is out of scope, combine observations: statically prove exact localized text is bound to the existing message API at the guard; natively prove guarded attempts fail with a nonempty platform failure, remain unposted, and leave every declared recorder movement/state unchanged. Do not claim pixel-level rendering.
4. Keep instrumentation structurally frozen when redesign is forbidden. After replacing only run/case/nonce values, ignore derived patch `index ...` headers and require every remaining instrumentation line to match.
5. Generate a fresh request identity, complete static admission, then replace the old task-owned receipt and invoke the shared route exactly once. Validate the request through the route's canonical JSON serialization, exact patch hashes, prepared/frozen/runner identity, oracle result and cleanup.
6. Preserve the original product elapsed and verdict. Report correction elapsed separately. Respect the measured phase breakdown; do not name an unmeasured cause as primary when another phase is demonstrably largest.
7. Qualify reuse honestly. Requalification of a previously investigated feature through a new route is not proof of solving a wholly unfamiliar task. If an older oracle already accepted a localized representation, a later parser miss is a local transfer error, not evidence of a shared-boundary defect.
8. Fast-forward the same PR branch, update its body for the replacement exact head/tree, wait for exact-head CI, perform local/remote/PR/blob read-back, publish only the requested compact terminal update, and leave the PR open/unmerged.

## Synthetic merge ref after a PR update

A cached local `refs/pull/<n>/merge` can reject a non-fast-forward update after the PR head changes. Fetch the live GitHub merge ref into `FETCH_HEAD` or a fresh temporary ref and inspect that exact object; never continue with the stale local merge commit. Verify its ordered parents and tree against the current base/head before claiming synthetic merge parity.
