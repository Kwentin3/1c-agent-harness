# Fast 1C product vertical slice

Use this reference when a product Goal asks for the shortest honest route from a business request to a local native receipt and an open PR, using an existing shared lifecycle rather than creating evidence infrastructure.

## Route

1. **Admit the exact base before starting the product clock.** Finish any explicitly required predecessor merge, verify its accepted head/tree, post-merge default-branch CI and issue closure, then create a clean task-owned worktree from that exact default-branch commit. Do not charge predecessor waiting to the successor feature clock.
2. **Read the live Goal and freeze only its acceptance.** Explicit exclusions such as “no mandatory RED/repeat/reviewer cycle” override generic workflow defaults. Ordinary correctable task defects remain autonomous; merge remains a separate owner boundary.
3. **Start one simple active-elapsed clock.** A nanosecond timestamp file is enough. Record only milestone times for context, change/static admission, native route, and terminal receipt. Do not build telemetry code. Report a missed target honestly even when the product passes.
4. **Gather narrow context with ordinary `rg`.** Search the exact current canonical snapshot, then ranged-read only the owner, earliest enforcement seam, preservation/bypass surface, user-facing form when required, and one nearby metadata precedent. Report repository-relative locators and the actual ranged-line total; compute that total rather than estimating it.
5. **Keep production ownership narrow.** For a document posting rule, prefer the object posting entry before posting initialization/movement preparation when server/external paths must also obey it. Leave `BeforeWrite` unchanged when invalid values must remain draft-saveable. A form control is UX, not the rule owner.
6. **Create task inputs, not a framework.** Retain only the request, exact production patch, necessary task-owned instrumentation/oracle, and final receipt plus a concise README. Preserve CRLF patch bytes and verify exact changed-path closure. Reconstruct both patches in a disposable copy before native work; when it sits under an ignored enclosing repository, set `GIT_CEILING_DIRECTORIES` so `git apply --no-index` cannot silently skip ignored paths.
7. **Validate generated structure before 1C.** Require one managed-client startup declaration, a current request identity, a server-call-only bridge, matched client/server identities and fresh response token, expected form IDs/metadata UUID uniqueness, XML well-formedness, and no unrelated production paths.
8. **Run the existing shared route.** The route must own disposable preparation, exact patch application, native 1C, task oracle, compact receipt and cleanup. Success is the route-produced receipt, not merely raw receipts or a manually rerun oracle.
9. **Handle oracle-only defects without rewriting business history.** If native behavior produced complete fresh client/server receipts but the host oracle rejected a representation detail (for example a platform-localized date string), inspect and correct only the task-owned parser, prove the corrected oracle against retained raw bytes, then rerun the shared route to obtain the authoritative route receipt. Report both invocations. Never retroactively label the failed route PASS, and do not perform an extra clean repeat after the final route succeeds.
10. **Audit and publish.** Re-read the committed receipt from the exact Git object, validate request/patch/input/result/cleanup binding, run repository gates, non-force push, open the PR, wait for exact-head CI, fetch the synthetic merge ref, and verify its tree equals the candidate tree when the base is unchanged. Leave the PR open unless a later exact owner decision authorizes merge.

## Date receipt parsing

1C may render a Date receipt with platform locale text rather than ISO 8601. A portable task oracle should accept only explicitly supported grammars, for example:

- ISO 8601 via `datetime.fromisoformat`;
- the observed invariant receipt grammar `M/D/YYYY H:MM:SS AM|PM` via a full-match parser.

Reject every other shape. Normalize only for semantic comparison; preserve and hash the original receipt bytes. This is a host-oracle adaptation, not a production behavior change.

## Compact terminal report

Include only:

- PR and exact receipt links;
- exact head/tree/base;
- business result;
- context file/ranged-line count;
- context, change/static, native and total active elapsed;
- native verdict, cleanup and exact-head CI;
- explicit open/not-merged state and owner-intervention count.

Use `PRODUCT PASS / COST FAIL` when the behavior passes but the elapsed target is missed, and name one factual dominant delay rather than hiding it inside a success verdict.
