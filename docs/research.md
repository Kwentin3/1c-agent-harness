# Существующие решения и стратегия повторного использования

Актуальность обзора: 25 августа 2026 года. Это входные данные для эксперимента; решение по source-tool этапа 0 уже подтверждено, а контекстный движок этапа 1 ещё должен пройти сравнение.

## Краткий вывод

Сейчас не следует форкать большой существующий проект и не следует писать собственный стек анализа. Первая проверяемая гипотеза — тонкая композиция нативных инструментов 1С, стандартных файловых операций и готового контекстного движка.

Форк — результат обнаруженной несовместимости, а не стартовая точка.

## Рекомендуемая стартовая композиция

1. Нативный Designer остаётся источником истины для снимка; прямые команды служат baseline, а проверенный checkout `cc-1c-skills` — внешний source-tool без глобальной установки.
2. `rlm-tools-bsl` проверяется как внешний контекстный движок этапа 1.
3. `rg` и обычные файловые операции остаются baseline и fallback.
4. Unica используется как comparator только на поддерживаемой платформе; `v8-runner-rust` остаётся кандидатом для сценариев, где будет доказана потребность в отдельном CLI.
5. Код нашего проекта ограничивается контрактами, воспроизводимым окружением, агентным протоколом и evals, пока не выявлен конкретный технический пробел.

## Когда допустим форк

Форк рассматривается, если эксперимент подтвердил хотя бы одно условие:

- требуемая legacy-версия не может быть поддержана внешним адаптером;
- upstream не принимает небольшое необходимое изменение;
- API или релизная политика не позволяют воспроизводимо закрепить поведение;
- модель безопасности нельзя сузить до read-only;
- проект перестал поддерживаться, а зависимость уже доказала продуктовую ценность.

До форка следует оценить внешнюю обёртку и вклад upstream. Форк означает постоянную обязанность сопровождать изменения платформы, исправления безопасности и расхождения с исходным проектом.

## Лицензионная граница

Запуск стороннего инструмента как отдельного процесса и включение его кода в производное решение — разные решения. До выбора лицензии `1c-agent-harness` сторонний код не копируется. Для каждой принятой зависимости должны быть зафиксированы версия, способ распространения и лицензия. Этот документ не является юридическим заключением.
